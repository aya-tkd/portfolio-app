# 外来ワークスペースと業務ダイアログ

外来業務は日常的に外来一覧を起点として進むため、外来一覧を基本ページ（親ワークスペース）として維持する。患者検索、受付、将来の予約・会計・患者詳細など、一覧から派生する短い業務はページ遷移ではなく共通ダイアログ領域で切り替える。

## 構成

```text
OutpatientWorkspace（親・状態保持）
├─ OutpatientList（一覧の表示と操作）
└─ WorkflowDialog（共通ダイアログ枠）
   └─ 動的に差し替える業務コンポーネント
      ├─ PatientSearchDialog
      ├─ ReceptionDialog
      ├─ ReservationDialog（将来）
      └─ BillingDialog（将来）
```

親ワークスペースが、一覧の検索条件・表示データ・展開状態・スクロール位置・現在の業務・選択患者・完了後の再読込要否を持つ。子コンポーネントは自分の業務だけを扱い、親が次の業務または中断を判断する。

## コンポーネント間の契約

- 親から子へは `props` で業務コンテキストを渡す。
- 子から親へは `emit` で結果だけを返す。子が親の関数や一覧データを直接操作しない。
- 例: 患者検索は `selected(patient)`、受付は `completed(receptions)` と `cancelled()` を返す。
- 親は結果を受けて、受付ダイアログへの切替、ダイアログ終了、外来一覧の必要な再読込を行う。

この分離により、患者検索は受付専用にせず、予約・会計・患者管理など複数の呼出元で再利用できる。

## ページ遷移との使い分け

外来一覧へ戻る短時間の業務はダイアログを使用し、一覧の状態を保つ。ログイン、管理領域への移動、業務全体の前提が変わる画面などは通常のページ遷移を使用する。

## 実装上の指針

Vueでは動的コンポーネント（`<component :is="...">`）または明示的な `v-if` でダイアログ内の業務コンポーネントを切り替える。親コンポーネントを肥大化させないため、一覧表示と業務フロー制御は `OutpatientList` と `OutpatientWorkspace` に分ける。

この方針は Issue #43 のレビューで合意した。現在のURLベースの仮実装は、このワークスペース構造へのリファクタリング対象である。
