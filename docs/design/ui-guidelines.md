# 画面・操作の共通設計ルール

Issue #1の設計で受けたユーザー指摘を基にした初期ルール。画面・操作ごとの設計はこの文書を参照し、例外は理由を記載する。色・寸法・ダイアログの詳細はモックでレビューし、必要に応じて調整する。

## 業務画面の組み立て

- 装飾より情報の識別と入力・確認の速さを優先する。白い入力領域、薄いグレーの見出し・境界線を基本にし、大きなカード、過大な余白、グラデーション、装飾目的のアイコンを使わない。
- 見出し→対象患者番号・モード→入力項目→下部の操作ボタンの順。入力は左上→右上→次の行の左→右とし、DOM・Tab順も一致させる。正のtabindexで順番を作らない。
- 患者氏名は姓・名、カナはセイ・メイを別々に入力・保存する。空白で氏名を分解する処理は作らない。
- ラベルは入力前に読める位置に固定し、プレースホルダーをラベルの代わりにしない。必須を文字でも示す。患者番号など編集不可の値は入力可能な欄と見分けられるようにする。
- 初期目安は本文14px、入力高34〜36px、項目間8〜12px、区切り16px。操作領域を詰めすぎず、フォーカス・エラー表示の場所を確保する。狭い画面では一列化し、横スクロールを避ける。
- ポートフォリオやモックの説明・検証用切替は業務フォームの外に置く。実画面に開発者向け説明を混ぜない。

## ボタンの語彙と意味

| 文言 | 意味 | 色・注意表示 |
|---|---|---|
| 新規 | 空の登録フォームを開く。DBへの登録はまだ行わない | グレー |
| 編集 | 選択した対象を編集可能にする／編集フォームを開く | グレー |
| 確認 | 内容を表示・確認する。保存の意味に使わない | グレー |
| 登録 | 入力内容をDBへ確定する。新規・編集の両方で使用 | 青系の塗り |
| 閉じる | 呼び出し元へ戻る。暗黙保存はしない | グレー |
| 戻る | 前の表示／確認前の入力状態へ戻る | グレー |
| 中止 | 入力中の変更を破棄する／進行中の操作を取りやめる | 警告アイコン＋文字。DB変更なしならグレー |
| 削除 | 対象を削除する。今回の患者画面には設けない | ゴミ箱／警告アイコン＋文字。DB変更なら赤系の塗り |

「登録する」「変更を保存」「OK」など同じ意味の別文言を混在させない。登録・編集の区別は画面タイトルとモードで示す。新しい動詞が必要になった場合は意味と分類をこの表へ追加する。

色はクリック後の作用で決める。通常のDB確定は青、破壊的なDB変更は赤、画面遷移や表示変更はグレー。「中止」でもDB上の状態を確定する機能なら色付きにして、対象と結果を確認する。アイコンだけのボタンや色だけの意味付けはしない。

「閉じる」は全画面・ダイアログ共通で下部操作領域の一番右下に配置する。主操作はその左とし、患者登録・編集では左から「登録 → 閉じる」の順にする。DOM・Tab順も表示順に揃え、狭い画面でも「閉じる」が最後・右下になる配置を維持する。危険操作がある画面では離して配置し、初期フォーカスを危険操作へ置かない。入力欄での意図しないEnter保存は避け、ボタンにフォーカスがある場合はEnter/Spaceで操作できるようにする。

## 配色の初期案

| 用途 | 値 |
|---|---|
| 本文 | `#212529` |
| 背景／セクション | `#f1f3f5` / `#e9ecef` |
| 入力領域 | `#ffffff` |
| 境界線 | `#adb5bd` |
| 通常の確定操作・フォーカス | `#0b5ed7` |
| エラー・破壊的な確定操作 | `#b02a37` |

Bootstrap＋共通CSSで定義し、画面ごとに固有色を増やさない。エラーには理由の文章を付け、文字・背景のコントラストとキーボードのフォーカスを確認する。

## 呼び出し画面とダイアログ

患者登録・編集は短い入力作業なので、呼び出し元の状態を保つモーダルダイアログを初期案とする。Webのモーダルは通常同じページ内に重ねて表示し、別のOSウィンドウを作らない。

- 開くときはダイアログ内へフォーカスを移し、表示中は背面を操作できなくする。Tab/Shift+Tabをダイアログ内に留め、閉じたら呼び出し元のボタンへ戻す。
- 閉じる・Escapeは同じ終了処理にまとめる。未保存の変更があれば破棄確認を出す。背面クリックだけでは閉じない。
- 保存成功を確認してから閉じ、呼び出し元へ患者IDと保存結果を通知する案。失敗時は開いたまま入力と項目別エラーを保持する。通信結果不明のときは保存成功と表示せず、自動再送しない。
- ブラウザの戻る／再読込はOSダイアログにはない経路なので、未保存保護と直URL時の戻り先を画面設計で定める。ブラウザ終了時の保護は完全には保証できない。
- 一覧完成前は呼び出し用の最小ホストから同じフォームを開く。将来の一覧・検索を先行実装しない。直URLはホスト＋同じフォームを表示する構成を検討する。

挙動の参照：[WAI-ARIA Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。この文書は業務操作の方針であり、実装時の検証を省略しない。
