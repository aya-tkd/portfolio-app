## 目的と画面遷移

外来一覧の左サイドバーにある「マスタ設定」から、外来一覧の検索条件・表示結果を破棄せずに共通ダイアログを開く。ダイアログのヘッダーは「外来業務 | マスタ設定」とし、左ペインの選択に合わせて右ペインを一覧または登録・編集フォームに切り替える。

患者マスタは「患者情報」、診療科・職種・予約枠マスタは「業務マスタ」に配置する。ユーザーマスタは「利用者・権限」から開く（Issue #16）。[ユーザーマスタ設計](user-master.md)に従って検索・登録・編集を行う。予約枠は[予約枠マスタ設計](reservation-slot-master.md)に従い、専用の検索・編集ペインを開く（Issue #62）。

## 一覧の共通動作

- 初期表示は全件を取得する。
- 文字列は部分一致、患者番号は完全一致で検索する。
- 一覧行を1件選択するまで「編集」は無効にする。
- 「新規」は空のフォーム、「編集」は選択した内部IDのフォームを右ペインに開く。
- 登録成功またはフォームの「閉じる」で同じマスタの一覧へ戻る。登録成功時は再検索して保存した行を選択する。
- 右ペインの一覧・フォームは内部だけをスクロールし、操作フッターは作業領域の最下部に置く。共通ダイアログの「閉じる」だけが外来一覧への復帰を行う。

| マスタ | 検索条件 | 一覧列 |
|---|---|---|
| 患者 | 患者番号、氏名・カナ氏名 | 患者番号、氏名、カナ氏名、生年月日、性別 |
| 診療科 | 診療科名・カナ名、利用状態 | ID、診療科名、カナ名、略名、表示順、利用状態 |
| 職種 | 職種名、利用状態 | ID、職種名、表示順、利用状態 |
| 予約枠 | 枠名、枠グループ、初期診療科、利用状態 | ID、枠名、グループ、曜日/期間、時間/間隔、各枠定員、初期科/医師、状態 |
| ユーザー | ユーザーID、氏名・カナ氏名、診療科、職種 | ID、氏名、カナ氏名、診療科、職種、利用状態 |

## 処理・責務

`OutpatientListWorkspace.vue` は外来一覧の状態を保持して共通ダイアログを開閉する。`MasterSettingsWorkspace.vue` は選択中マスタ、検索条件、選択行、一覧／フォームの表示状態を持つ。各 `api.js` は検索条件をGETクエリへ変換するだけで、Rails側のControllerがActive Recordで検索してJSONを返す。

`PatientForm.vue`、`DepartmentForm.vue`、`OccupationForm.vue` は単独画面で使うダイアログとしての振る舞いを保ちつつ、`embedded` 指定時は右ペイン内フォームとして表示する。保存の検証・CSRF・再送しない扱いは既存フォームと同じである。

## HTTPとデータ

| HTTP | 用途 | 条件 |
|---|---|---|
| GET `/api/patients` | 患者一覧 | `patient_number` は完全一致、`name` は部分一致 |
| GET `/api/departments` | 診療科一覧 | `keyword` は名称・カナ名の部分一致、`active` は完全一致 |
| GET `/api/occupations` | 職種一覧 | `keyword` は名称の部分一致、`active` は完全一致 |
| GET `/api/reservation_slots` | 予約枠一覧 | 枠名部分一致、グループ・初期診療科・状態のAND、50件ページング |

既存の `mst_patients`、`mst_departments`、`mst_occupations` を参照・更新する。テーブル定義やMigration、削除、認証・認可はこの画面の対象外である。
