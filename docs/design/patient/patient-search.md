# 患者検索

- 対象Issue: #33
- 画面URL: `/patients`
- 対象テーブル: `mst_patients`（Readのみ）
- 関連画面: [患者登録・編集](patient-form.md)

## 目的と利用の流れ

患者番号または氏名・カナ氏名で患者を探し、一覧から一人を選んで既存の患者登録・編集画面を開く。患者番号は完全一致、氏名・カナ氏名は部分一致で検索する。氏名の入力に含まれる半角・全角空白は照合時に無視する。

初期版では条件未入力の検索は全件表示とする。複数の条件を入れたときはAND条件で絞り込む。生年月日は重複確認など別の用途が必要になった時点で追加検討する。

## 画面・操作

1. 上部の検索条件で「患者番号」または「氏名・カナ」を入力し、`検索`を押す。
2. 中央の一覧から患者を一人選択する。選択行は色で示す。
3. 下部の`新規`は患者登録を、`編集`は選択した患者の編集を既存ダイアログで開く。未選択時の`編集`は無効とする。
4. 登録・編集の保存後は条件を保持して再検索し、結果に含まれれば保存した患者を再選択する。
5. `閉じる`は画面右下に固定し、患者管理の入口へ戻る。

検索・新規・編集・閉じるはDBを即時更新しない処理のため、共通UI規約どおりグレーのボタンとする。登録・編集ダイアログ内でDBを更新する`登録`だけは色付きとする。

## APIと処理範囲

`GET /api/patients?patient_number=<患者番号>&name=<氏名・カナ>` を利用する。Viteが同一オリジンのAPI要求をRailsへ転送し、`backend/config/routes.rb` の `resources :patients, only: %i[index show create update]` が `Api::PatientsController#index` を選ぶ。Controllerは許可済みの二つのクエリだけを `Patient.search` へ渡す。

`Patient.search` は `mst_patients` を `id` 昇順で読む。患者番号は完全一致、氏名とカナ氏名は姓・名を連結した値への部分一致である。検索値はプレースホルダとして渡し、SQL文字列の組み立てに利用しない。新規テーブル、migration、外部連携、認証・認可、削除、ページング・ソートは本Issueの対象外とする。

## テスト観点

- 患者番号の完全一致、氏名・カナ氏名の部分一致、空白無視、複数条件のAND
- 条件未入力時の全件表示、該当なし、通信失敗
- 一覧選択、未選択時の編集不可、新規・編集のダイアログ起動
- 保存後の条件保持・再検索・同一患者の再選択
- Rails API/Model、フロントAPI、ブラウザ経由のE2E

設計承認時の画面モックは[HTMLモック](mocks/patient-search.html)を参照する。
