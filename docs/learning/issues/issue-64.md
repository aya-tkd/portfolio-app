# Issue #64 学習記録

通常記録。親Issue #64、設計 #72、テスト #73、セッション #74。

| 観点 | 根拠 | 前→後 | 確かさ | 次の機会 |
|---|---|---|---|---|
| Vueと画面処理・APIの分担 | App.vueからの直呼出と患者検索・外来一覧の業務導線が別であることを指摘（チャット） | L2→L2 | 確認あり | 親から患者IDを渡すpropsと、閉じるイベントの経路を読む |
| Model・Service・DTO | 枠定義と予約実績、診察と設備の親子・同日条件を業務レビューで具体化（チャット） | L2→L2 | 暫定を維持 | 空き照会後に他の予約が入る場合の保存時検証を読む |

設計・画面の了承だけではRailsの永続化やJavaScript構文の習得根拠としないため、その他の段階も維持する。

処理順は `ReservationWorkspace.vue` の画面内確定 → `api.js` のPOST → `AppointmentsController#create_bulk` → `Reservation::Book` のトランザクション → 予約と利用数の保存。GET時の空きは保存保証ではなく、SQLiteでは最初に書込み権を取得してから保存時点の有効マスタ・予約数を読み直す。
