# Definition of Done

作業単位を完了する前に、該当する項目を確認します。

- Issueの目的と受入条件を満たしている
- 変更範囲が依頼・Issueの範囲内である
- 必要なテストまたは検証を実施している
- セキュリティと秘密情報の確認を行っている
- README、Architecture、Design、ADR、Processなど関連文書と整合している
- UIまたは処理を変更した場合、影響する画面・操作設計Docを更新し、表示・操作の変更はHTMLモックにも反映している
- データ構造を変更した場合、migrationとテーブル設計Docを更新している
- 親Issue、Sub-issue、PR、設計Docのリンクが追跡可能である
- 不要な重複文書や古い記述を残していない
- AIの担当範囲と人間のレビュー・判断が追跡可能である
- 未実施事項や既知の制約をIssueまたはPRに記録している

## PRへ進む条件

- 現在の設計版に対する人間の承認が有効である
- AC識別子とテストが対応し、対象commit・環境・コマンド・結果が追跡できる
- 必要なチェックが成功している。未実行を成功扱いせず、対象外なら理由と代替検証を残す
- UI変更は実装画面でも正常表示・入力エラー・主要操作を確認する。検証不能なら制約を明記する
- レビューの重大な指摘が解消され、PR修正後も検証結果が有効である
- 初回実装や起動方法の変更時はREADMEのセットアップ・起動・テスト手順を更新する

PR準備完了とIssue完了を区別します。Issue完了は人間によるmergeと親IssueのCloseを確認した後です。セッションログに成果、判断、検証リンク、短い学習の振り返り、改善候補を記録します。
